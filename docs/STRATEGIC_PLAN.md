# Horizon Pangenome Suite: Strategic Plan and Risk Mitigation

> **Status Note (2026-11-19):** All 9 target pangenome binaries in `src/bin/` (`horizon_wga` including `--graph`, `horizon_merge`, `horizon_guide`, `horizon_eval`, `horizon_gfa`, `horizon_clean`, `horizon_resolve`, `horizon_lift`, `bench_chr1`) now have unit tests (`46` passing tests + `1` ignored: `37` in `src/lib.rs` and `1` in each of the `9` binaries; `cargo clippy --all-targets -- -D warnings` clean). Only `horizon_gfa stats` supports single-pass `"-"` `stdin` streaming; two-pass tools (`horizon_clean`, `horizon_resolve`, `horizon_lift`) and `horizon_wga` require seekable file paths. Remaining engineering limits (e.g., `KARLIN_MDL_COEFF = 0.55` and `LASTZ12` fallback `HashMap`s) are documented below.

## 1. The Vision: Composition over Monolith
The history of bioinformatics alignment is a history of composition: `lastz` (pairwise) feeding into `multiz` (MSA), or `cactus` (graph) feeding into `hal` (storage). The vision for `horizon-aligner` is to unify these capabilities under a single framework based on Minimum Description Length (MDL) and E-graphs.

Rather than building a monolithic "run-all" executable, the target architecture is a suite of specialized tools (`horizon_clean`, `horizon_wga`, `horizon_resolve`, `horizon_lift`) that compose cleanly—following the Unix-pipe precedent of `gfatools` and `odgi`—wherever single-pass or indexed streaming is feasible.

## 2. Current Foundation and Known Gaps
* **MDL Bit-Savings (`src/bocpd.rs`, `src/mdl/`):** We replace classical substitution matrices with BOCPD joint-pair bit-savings (`joint_pair_bits`, skipping `'N'` bases in `bocpd_gc_profile`), use normalized Pair-HMM transitions (`src/mdl/dp.rs`, `src/mdl/dag.rs`: `M` and `Ix`/`Iy` outgoing probabilities sum to `1.0`), and adaptively estimate `identity_prior` (clamped `[0.60, 0.72]`), `gap_open_bits`, and `gap_extend_bits` from LCB anchors via `estimate_hmm_params` (`src/mdl/mod.rs`), wired into `mdl_xdrop_extend_with_params` (in `horizon_wga --graph`, `estimate_dag_hmm_params` adapts `identity_prior` from `<=2000` bp of exact `MASK_W10` seed hits and leaves `gap_open_bits`/`gap_extend_bits` at defaults). Structural chaining thresholds (`KARLIN_MDL_COEFF = 0.55`, `max_gap_bp = 2400`, `hsp_threshold`, `min_block_bits`) remain fixed heuristics. `ContigIndex` (`src/seeding/mod.rs`) now uses a compact `FlatSeedIndex` (`12 bytes/entry` post-build sorted `Vec<u64>` + `Vec<u32>`, peaking transiently at `~28 bytes/entry` during `build`, with on-the-fly reverse-complement coordinates; `ContigIndex` still retains `seq_rc` and `MASK_LASTZ12`/`MASK_LASTZ11` fallbacks still use `HashMap`s). Together with bundled `488b020` `rev_offsets`/`bocpd`/`dp` edits, `20 Mbp chr6 q-arm` peak RSS fell from `5,863.3 MB` to `2,409.7 MB` and `chr6` 5 Mbp pericentromere RSS fell from `3,084.5 MB` to `1,048.2 MB`.
* **E-Graphs for Structural Variants (`src/egraph.rs`, `src/bin/horizon_resolve.rs`):** Congruence-closure rewriting uses `MdlCostModel` (`extract_min_mdl_cost`: catalog pointer bits $\log_2 K$, `seq`/`inv` `1.0` bit, `dup` copy header `2.5` bits + $H_2(d) + d \log_2 3$ residual bits) and runs both inside `horizon_wga --resolve-dups` (benchmarked on 5 Mbp MHC/HLA and 20 Mbp `chr6` q-arm) and standalone `horizon_resolve` over anchor-bounded snarl/bubble windows in GFA `P`/`W` lines (`horizon_resolve --collapse-dups` updates `W`-line end coordinates and preserves `P`/`W` tags, while `L`-link rewriting remains open). Real HPRC `GRCh38` vs `CHM13` `chr22` and `chr6` pericentromere 5 Mbp loci are benchmarked in `docs/BENCHMARK_RESULTS.md`.
* **Buffered GFA Streaming Parser (`src/gfa/mod.rs`, `src/bin/horizon_gfa.rs`):** `stream_gfa` provides a buffered line-streaming reader for `H`/`S`/`L`/`P`/`W` GFA v1.0/v1.1 records (ignoring `C`/`J`/`U`/`O` records, coercing non-numeric `W` coordinates to `0`, and supporting `.gfa`, multi-member BGZF `.gfa.gz` via `MultiGzDecoder`, and uncompressed `"-"` `stdin`, with unit tests for empty `L`-line orientations and `.gfa.gz`). It is **not** zero-copy (it allocates owned `String`/`Vec<u8>` fields per record), but on the 12 GB HPRC v1.0 Minigraph-Cactus graph (measured at `b857377`, not re-timed on `488b020`) `horizon_gfa stats` streamed `81.4M` segments (`3.29 Gbp`) and `113.0M` links in `88.84s` at **97.1 MB peak RSS**, and `horizon_gfa extract` extracted `GRCh38.chr22` + `CHM13.chr22` in `166.73s` at **456.1 MB peak RSS**. While modern indexed/disk-backed representations (`GBZ` / `GBZ-base` by Sirén et al., `gfaidx`) also address subgraph queries without full-graph RAM materialization, native streaming gives Horizon direct `H`/`S`/`L`/`P`/`W` interoperability without external `vg`/`odgi` dependencies.

## 3. Strategic Adjustments & Risk Mitigations

### A. Avoid a Proprietary "Walled Garden" Format
**Risk:** Binary-only formats with heavy external C dependencies (such as HDF5 `.hal` in `Cactus`) complicate downstream parsing and ecosystem interoperability. (For backwards-compatibility, `horizon-aligner` currently includes a pure-Rust `.hal` reader/writer in `src/hal/` via `horizon_wga --hal-info`, which will remain optional.)
**Mitigation:** We will **not invent a proprietary binary format** for the pangenome suite. Target tools will exchange standard GFA (v1.0/v1.1) and MAF (plus VCF where variant output is added), using only valid GFA optional tags/comments (e.g., `HB:i:`, `XS:i:`, `YS:i:`, `ST:Z:`, `# EG:Z:`). Any required random-access indexing (for `S`-line sequences or `W`/`P` coordinates) will use lightweight, optional sidecar files (analogous to `.fai`/`.gzi`), not a locked database.

### B. Emulate Unix Composition Where Topology Allows
**Risk:** Building a monolithic CLI that couples all stages internally.
**Mitigation:** Support `stdin`/`stdout` GFA/MAF streaming on single-pass linear filter/transform tools (`horizon_gfa stats`), while acknowledging that multi-input or two-pass random-access stages (`horizon_wga --graph --query`, `horizon_clean`, `horizon_resolve`, `horizon_lift`) require seekable file paths or sidecar indices rather than pure single-pass `stdin` piping.

### C. Localize the E-Graphs (Prevent Combinatorial Explosion)
**Risk:** E-graph saturation under associative `seq` rules grows combinatorially (hitting `max_nodes = 800` at small block counts) and cannot scale to whole chromosomes.
**Mitigation:** Strict **bubble extraction** via a topological decomposition pass (analogous to `vg` snarls / `smoothxg`) rather than single-pass unsorted GFA streaming. Once tangled subgraphs ("hairballs") are isolated into bounded bubbles, the E-graph resolves each bubble locally and writes the resolved path back into the graph.

### D. Target Graph Tooling Gaps First
**Risk:** Competing head-on against `lastz` or `minimap2` on routine pairwise alignment offers limited differentiation.
**Mitigation:** Focus our next implementation and benchmarking milestones on pangenome graph tooling (`horizon_clean` real-data severing, `horizon_resolve` `L`-link rewriting, `horizon_lift` truth baselines, and completed full-chromosome HPRC `GRCh38` vs. `CHM13` evaluation), where MDL abstention and bounded structural resolution address concrete pain points in complex loci.
