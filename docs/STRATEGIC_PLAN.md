# Horizon Pangenome Suite: Strategic Plan and Risk Mitigation

> **Status Note (2026-11-19):** All 9 target pangenome binaries in `src/bin/` (`horizon_wga` including `--graph`, `horizon_merge`, `horizon_guide`, `horizon_eval`, `horizon_gfa`, `horizon_clean`, `horizon_resolve`, `horizon_lift`, `bench_chr1`) now have unit tests (`47` passing tests + `1` ignored: `37` in `src/lib.rs` and `10` across the `9` binaries; `cargo clippy --all-targets -- -D warnings` clean). `horizon_gfa stats` streams `"-"` `stdin` in a single pass, `horizon_clean --gfa -` spools `stdin` to a temporary file for two-pass cleaning, and `horizon_resolve`/`horizon_lift`/`horizon_wga` require seekable file paths. Remaining engineering limits (e.g., `KARLIN_MDL_COEFF = 0.55` and `LASTZ12` fallback `HashMap`s) are documented below.

## 1. The Vision: Composition over Monolith
The history of bioinformatics alignment is a history of composition: `lastz` (pairwise) feeding into `multiz` (MSA), or `cactus` (graph) feeding into `hal` (storage). The vision for `horizon-aligner` is to unify these capabilities under a single framework based on Minimum Description Length (MDL) and E-graphs.

Rather than building a monolithic "run-all" executable, the target architecture is a suite of specialized tools (`horizon_clean`, `horizon_wga`, `horizon_resolve`, `horizon_lift`) that compose cleanly—following the Unix-pipe precedent of `gfatools` and `odgi`—wherever single-pass or indexed streaming is feasible.

## 2. Current Foundation and Known Gaps
* **MDL Bit-Savings (`src/bocpd.rs`, `src/mdl/`):** We replace classical substitution matrices with BOCPD joint-pair bit-savings (`joint_pair_bits`, skipping `'N'` bases in `bocpd_gc_profile`), use normalized Pair-HMM transitions (`src/mdl/dp.rs`, `src/mdl/dag.rs`: `M` and `Ix`/`Iy` outgoing probabilities sum to `1.0`), and adaptively estimate `identity_prior` (clamped `[0.60, 0.72]`), `gap_open_bits`, and `gap_extend_bits` from LCB anchors via `estimate_hmm_params` (`src/mdl/mod.rs`), wired into `mdl_xdrop_extend_with_params` and `horizon_wga --graph` (`estimate_dag_hmm_params`, which now also calibrates `gap_open_bits`/`gap_extend_bits` from adjacent seed pairs). Structural chaining thresholds (`KARLIN_MDL_COEFF = 0.55`, `max_gap_bp = 2400`, `hsp_threshold`, `min_block_bits`) remain fixed heuristics. `ContigIndex` (`src/seeding/mod.rs`) now uses a compact `FlatSeedIndex` (`12 bytes/entry` post-build sorted `Vec<u64>` + `Vec<u32>`, peaking transiently at `~28 bytes/entry` during `build`, with on-the-fly reverse-complement coordinates; `ContigIndex` still retains `seq_rc` and `MASK_LASTZ12`/`MASK_LASTZ11` fallbacks still use `HashMap`s). Together with bundled `488b020` `rev_offsets`/`bocpd`/`dp` edits, `20 Mbp chr6 q-arm` peak RSS fell from `5,863.3 MB` to `2,409.7 MB` and `chr6` 5 Mbp pericentromere RSS fell from `3,084.5 MB` to `1,048.2 MB`.
* **E-Graphs for Structural Variants (`src/egraph.rs`, `src/bin/horizon_resolve.rs`):** Congruence-closure rewriting uses `MdlCostModel` (`extract_min_mdl_cost`: catalog pointer bits $\log_2 K$, `seq`/`inv` `1.0` bit, `dup` copy header `2.5` bits + $H_2(d) + d \log_2 3$ residual bits) and runs both inside `horizon_wga --resolve-dups` (benchmarked on 5 Mbp MHC/HLA and 20 Mbp `chr6` q-arm) and standalone `horizon_resolve` over anchor-bounded snarl/bubble windows in GFA `P`/`W` lines (`horizon_resolve --collapse-dups` updates `W`-line end coordinates, preserves `P`/`W` tags, prunes unused `L` links when `P`/`W` records exist, and emits any missing shortcut `L` links). Real HPRC `GRCh38` vs `CHM13` `chr22` and `chr6` pericentromere 5 Mbp loci are benchmarked in `docs/BENCHMARK_RESULTS.md`.
* **Buffered GFA Streaming Parser (`src/gfa/mod.rs`, `src/bin/horizon_gfa.rs`):** `stream_gfa` provides a buffered line-streaming reader for `H`/`S`/`L`/`P`/`W` GFA v1.0/v1.1 records (ignoring `C`/`J`/`U`/`O` records, coercing non-numeric `W` coordinates to `0`, and supporting `.gfa`, multi-member BGZF `.gfa.gz` via `MultiGzDecoder`, and uncompressed `"-"` `stdin`, with unit tests for empty `L`-line orientations and `.gfa.gz`). It is **not** zero-copy (it allocates owned `String`/`Vec<u8>` fields per record), but on the 12 GB HPRC v1.0 Minigraph-Cactus graph (current build) `horizon_gfa stats` streamed `81.4M` segments (`3.29 Gbp`) and `113.0M` links in `99.97s` at **97.0 MB peak RSS**, and `horizon_gfa extract` extracted `GRCh38.chr22` + `CHM13.chr22` in `183.29s` at **456.4 MB peak RSS**. While modern indexed/disk-backed representations (`GBZ` / `GBZ-base` by Sirén et al., `gfaidx`) also address subgraph queries without full-graph RAM materialization, native streaming gives Horizon direct `H`/`S`/`L`/`P`/`W` interoperability without external `vg`/`odgi` dependencies.

## 3. Strategic Adjustments & Risk Mitigations

### A. Avoid a Proprietary "Walled Garden" Format
**Risk:** Binary-only formats with heavy external C dependencies (such as HDF5 `.hal` in `Cactus`) complicate downstream parsing and ecosystem interoperability. (For backwards-compatibility, `horizon-aligner` currently includes a pure-Rust `.hal` reader/writer in `src/hal/` via `horizon_wga --hal-info`, which will remain optional.)
**Mitigation:** We will **not invent a proprietary binary format** for the pangenome suite. Target tools will exchange standard GFA (v1.0/v1.1) and MAF (plus VCF where variant output is added), using only valid GFA optional tags/comments (e.g., `HB:i:`, `XS:i:`, `YS:i:`, `ST:Z:`, `# EG:Z:`). Any required random-access indexing (for `S`-line sequences or `W`/`P` coordinates) will use lightweight, optional sidecar files (analogous to `.fai`/`.gzi`), not a locked database.

### B. Emulate Unix Composition Where Topology Allows
**Risk:** Building a monolithic CLI that couples all stages internally.
**Mitigation:** Support `stdin`/`stdout` GFA/MAF streaming on single-pass linear filter/transform tools (`horizon_gfa stats`), while acknowledging that multi-input or two-pass random-access stages (`horizon_wga --graph --query`, `horizon_clean`, `horizon_resolve`, `horizon_lift`) require seekable file paths or sidecar indices rather than pure single-pass `stdin` piping.

### C. Localize the E-Graphs (Prevent Combinatorial Explosion)
**Risk:** E-graph saturation under associative `seq` rules grows combinatorially (hitting `max_nodes = 800` at small block counts) and cannot scale to whole chromosomes.
**Mitigation:** Strict **bubble extraction** via a topological decomposition pass (analogous to `vg` snarls / `smoothxg`) rather than single-pass unsorted GFA streaming. Once tangled subgraphs ("hairballs") are isolated into bounded bubbles, the E-graph resolves each bubble locally and writes the resolved path back into the graph.

### D. Target Graph Tooling Gaps First
**Risk:** Competing head-on against `lastz` or `minimap2` on routine pairwise alignment offers limited differentiation.
**Mitigation:** Focus our next implementation and benchmarking milestones on pangenome graph tooling (`horizon_clean` real-data severing, `horizon_resolve` `L`-link rewriting, `horizon_lift` truth baselines, and completed full-chromosome HPRC `GRCh38` vs. `CHM13` evaluation), where MDL abstention and bounded structural resolution address concrete pain points in complex loci.

## 4. Literature Audit & Next Speedups (from 14 Corpus Papers)

Cross-checking `horizon-aligner` against the 14 newly processed papers in the library (`rissanen_1978`, `schwarz_1978`, `grunwald_2007`, `durbin_1998`, `ma_2002`, `morgulis_2006`, `paten_2018`, `sena_2026`, `guarracino_2022`, `heumos_2024`, `lee_2002`, `gao_2021`, `jiang_2008`, `miller_2020`) surfaced concrete fixes and next-tier speedups:

### Applied Immediately
1. **$O(H \log |\text{active}|)$ LCB Chaining (`src/seeding/mod.rs`):** Replaced the $O(H \cdot |\text{active}|)$ linear scan in `cluster_strand_lcbs` with `BTreeSet` indices on `(lx, id)` (expiration) and `(ly, id)` (local `y`-window lookup), cutting `20 Mbp chr6 q-arm` runtime from `47.51s` to `38.23s` (`seed_end=0.00s`) with bit-for-bit identical outputs.
2. **Principled `N`-Base Emissions & Tail-Preserving BOCPD (`src/bocpd.rs`):** `joint_pair_bits` now returns `0.0` bits (uninformative `P_joint = P_null`) for ambiguous/`N` bases instead of `-2.0` bits, and `bocpd_gc_profile` folds `max_run` overflow probability into the oldest bin rather than dropping mass.
3. **Optimal Non-Periodic Weight-11 Seed (`src/seeding/mod.rs`):** Exported `MASK_PH11_18` (`111010010100110111`, Ma et al. 2002) alongside `MASK_PRIMARY_11_15` (which is period-3).

### Next-Tier Speedups & Architectural Refactors
1. **Adaptive Banded + SIMD DAG DP (`src/mdl/dag.rs`, Gao et al. 2021 `abPOA`):** Replace the 9 dense `f64` matrices (`72 B/cell`, unbanded) with per-node adaptive banding + SIMD `f32`/`i16` DP (10–50× speedup, >10× RAM cut) and replace all-reachable seeding in `align_seq_to_dag_seeded` with DAG anchor chaining.
2. **ODGI-Style `u32` Interned `PackedGraph` + Jaccard Liftover (`src/gfa/mod.rs`, `horizon_lift.rs`, Guarracino et al. 2022; Heumos et al. 2024):** Intern segment names once into dense `u32` IDs with CSR adjacency and zero-copy GFA streaming (`GfaRecordRef<'_>`), add `k`-step multiset Jaccard tie-breaking in `horizon_lift`, and sort nodes via 1D PG-SGD / path order.
3. **Linear-Time Snarl / Ultrabubble Decomposition (`horizon_resolve.rs`, Paten et al. 2018; Sena et al. 2026):** Replace 16-step 1D walk windowing with $O(|V| + |E|)$ biedged SPQR-tree / cactus decomposition, normalize `seq` chains to avoid associativity blowup in `saturate_synteny`, and compute per-bubble divergence instead of a global `--divergence` flag.
4. **SDUST Pre-Masking + PH2 Double-Hit Gating + `FlatSeedIndex` Fallbacks (`src/seeding/mod.rs`, `src/mdl/mod.rs`, Morgulis et al. 2006; Ma et al. 2002):** Precompute one $O(N)$ SDUST triplet mask per contig (catching di/trinucleotide repeats missed by 1-mer `is_low_complexity_window`), require two-hit diagonal gating before HSP extension in fallback seeders, and move `LASTZ12`/`LASTZ11` from `HashMap`s to `FlatSeedIndex`.
5. **Pure Forward-Backward MEA Decoding (`src/mdl/dp.rs`, Durbin et al. 1998 Ch. 4):** Replace the Viterbi + posterior-filter hybrid in `banded_mdl_gap_with_params` with Maximum Expected Accuracy (MEA) decoding over `exp(fm + bm - z_fwd)`, eliminating the 3 Viterbi `BandGrid`s (~30% DP memory savings) and Viterbi gap-misplacement artifacts.
